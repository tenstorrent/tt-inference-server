# Gemma 4 31B CI startup failures on QB2 runners

👽 During Gemma 4 31B agentic evaluations on 9–10 October 2026, the shared `bh-qb-ge` pool assigned jobs to hosts where setup failed before evaluation. The same inference-server commits and pinned Metal image completed evaluation on the other hosts linked below. This establishes runner-associated failures, not a proven hardware root cause.

| Affected host | Failed CI job | Completed evaluation elsewhere |
| --- | --- | --- |
| `p04t07` | [Run 37962790734](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/37962790734): a stopped, unowned Docker container caused Shield to refuse cleanup and hardware execution. | `p05t02`: [run 37963842946](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/37963842946), same model commit and image, after a separate TB2.0 workflow allowlist fix. |
| `p04t05` | [Run 38001414052](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/38001414052): four-chip fabric mapping failed at `topology_mapper.cpp:556`. This host also emitted [800 MHz versus 1350 MHz AICLK warnings](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/37963243142). | `p05t05`: [run 38010947583](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/38010947583), same C8 model commit, image and ten cases (wrapper added hold jobs). `p04t05` had itself completed C8 SWE earlier, so the failure was not constant. |
| `p05t06` | [Run 38043892436](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/38043892436): the same fabric mapping error after this host had completed other Gemma work. | `p05t05`: [run 38048296731](https://github.com/tenstorrent/tt-agentic-bringup-qb2/actions/runs/38048296731), same model and wrapper commits, image and twenty cases. |

Gemma requests `FABRIC_1D_RING` with a `(1, 4)` device mesh. Both fabric failures happened during ring fabric initialization: the topology mapper could not fit the four logical nodes onto the discovered `2x2_Mesh_flat` four-ASIC grouping. No line-fabric comparison was run, so the evidence does not show whether ring connectivity specifically caused the failures or whether line fabric would work.

To keep long evaluation jobs off these hosts, I added temporary [`hold-*` jobs](https://github.com/tenstorrent/tt-agentic-bringup-qb2/blob/mvasiljevic/gemma-tb2-ci/.github/workflows/manual-tt-shield-dispatch.yml). They occupy an affected runner for up to 170 minutes, checking either for existing containers or an exact runner name. The hold steps do not remove containers or reset devices. This required manual assignment checks, repeated dispatches, and renewals as holds expired; several model jobs were canceled before hardware work and reissued on other hosts.

**Requested:** Resolve ownership of the container on `p04t07`; check four-chip ring connectivity and topology discovery on `p04t05` and `p05t06`; investigate the 800 MHz AICLK warning; and provide a maintained quarantine or health label so affected runners can be excluded without sleeping Actions jobs. The fabric failures could reflect intermittent host state or a host-sensitive software/discovery issue; these comparisons do not prove defective hardware.
